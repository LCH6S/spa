# Meta POS 激活改造评审过程与决策记录

截至 2026-11-25。按讨论阶段记录业务判断、原型反馈和方案变化。当前需求以 [PRD V0.2](meta-pos-device-activation-prd.md) 为准。原型部署、实际业务联调与评审结果分别记录。

## 1. 业务问题与场景

| 讨论主题 | 确认结果 |
|---|---|
| 为什么改造 | 现有 Meta POS 使用扫码激活，实际配机通常在下单、派机和备机阶段已经知道设备归属。将分配前置，POS 用本机设备号查任务，现场核对后激活。 |
| 六个场景 | 新开门店申请新机、换修、移机、回收、原店维护重新激活、门店收到设备后自行开通银行卡。新店由品牌方通过 AE 提出配机需求。换修沿用先寄回旧机、再发起换修的业务顺序。 |
| 人员与操作端 | AE 使用 CRM，实施和运营使用运营平台，实施或店员使用 Meta POS。新机下单、接单、激活、发货、收货启用各自有交接结果。 |
| 发货条件 | 订单备注或派机清单已提供完整通联参数时，完成收钱吧终端和银行卡激活并验机后发货。未提供完整通联参数时，可先启用收钱吧终端并验机发货，后续由 AE 或运营补录并通知店员开通。 |
| 文档组织 | 业务 BRD 按六个端到端场景组织，场景内有高层旅程、业务流程图和各环节的子旅程，用户与操作端分列。PRD 按运营平台、Meta POS 端操作、CRM 写功能，端到端章节改按实施、AE 和运营展开。 |

过程产出包含 [初版 BRD V0.1](meta-pos-device-activation-brd.md) 和 [业务 BRD V0.2](meta-pos-device-activation-brd-business.md)。

## 2. 分配与设备模型的演进

| 前期讨论 | 当前口径与原因 |
|---|---|
| 导入直接在品牌门店下建设备实体，以设备 ID 承载激活信息 | 分配成功后每台先建一条激活任务，以实物设备号为核心。收钱吧终端成功且实际归属匹配后再生成当前设备记录。运营和实施通过任务与设备两个视图分别排查待办和在用设备。 |
| 扫码获取激活信息 | 新 Meta POS 按设备号查询有效任务，读取目标归属、激活码和预分配参数。旧轻 POS 继续沿用旧办事路径。 |
| 设备列表一度展示已分配但未激活记录 | 本期新流程下，待处理记录在设备激活任务列表查找，POS 激活管理只承接其已激活设备。旧终端记录按原流程处理。 |
| 反激活后在设备列表继续展示历史设备 | 当前设备退出有效列表，历史留在原任务。复用同一设备号时先完成原终端解绑，再创建新任务。设备自动检测反激活，现场无需重启。 |

同一设备号只能有一条有效分配，有待处理任务或仍绑定有效设备时拦截另一笔分配。操作完成与历史追踪分别以当前设备、原任务为准。 [PRD](meta-pos-device-activation-prd.md)

## 3. 运营平台的交互收敛

### 3.1 导入批次

- 在「集团客户 → IOT 管理」下新增入口。页名从「POS 设备分配」经「Meta POS 激活」调整为「激活任务管理」，保留现有「POS 激活管理」菜单。
- 一次上传对应一批。按收单机构下载对应 Excel 模板，输入批次备注，经历「上传 → 检查 → 执行」。设备号、收钱吧门店号和激活码必填，通联商户号和终端号一起填或一起留空。
- 检查阶段分为「设备分配预览」和「检查未通过」。通过项按品牌 → 门店分组，显示品牌名称与编号、门店名称与编号及收钱吧门店号。实施离开后能从原批次继续，有权限的运营或实施可接手，记录实际操作人。
- 执行后用批次作为完整视图，展示逐台任务和「导入失败」两类内容。早期讨论的「执行成功／执行失败／未执行」三页签已被这一方案替代。检查未通过和执行失败在失败列表按阶段区分，作废单独计数。导入进度表达系统阶段，统计表达逐台结果。整批检查均未通过自动显示「已取消」，部分通过可以执行。待执行批次也可手动取消。
- 下载失败清单只包含失败行，原模板列顺序保留，末尾增加失败原因。修正后作为新批次上传，导入忽略原失败原因列。增补设备以新批次提交。
- 批次列表支持批次号、备注、设备号、提交人、上传时间范围和导入进度筛选。时间范围精确到分钟。提交人和上传时间接近列表末尾，操作列最后。批次检查和结果页通过面包屑等现有入口导航。

### 3.2 任务与设备管理

- 单台分配使用单列弹窗。输入收钱吧门店号后回显目标品牌和门店，再录入设备号、激活码和适用的银行卡参数。创建成功弹窗提供「返回」「查看详情」，查看详情进入任务列表。批次详情所列任务与全局任务列表共用操作。
- 任务状态最终统一为「待处理」「已完成」「已作废」。列表在设备号前展示生成时间，并支持生成时间范围筛选。任务详情显示提交人、目标门店、脱敏激活码、预分配银行卡参数和激活历史。任务结果由收钱吧终端激活决定，银行卡按独立流程办理。
- 待处理任务可更正激活码和预分配银行卡参数。单条或批量作废采用相同条件。批量操作进入选择模式后支持跨页选择、全选、清空及取消。已开始激活且结果未确定的任务先核对结果。
- 激活记录保留每次结果及原因。成功行显示设备 ID 和收钱吧终端号，终端仍绑定时可进入设备详情。实际门店与目标门店不同的失败行写明实际收钱吧门店号，并进入自动解绑处理。只有成功激活后又反激活的成功行显示「已解绑」。
- 设备详情展示设备、归属、收钱吧终端、银行卡及设备上报信息。激活记录在任务详情查看，设备详情的删除入口已取消。银行卡参数变更记录按字段逐行展示，系统初始记录的操作端显示「—」，手工修改记录实际操作者和操作端。

## 4. POS 端确认与异常

| 讨论主题 | 当前口径 |
|---|---|
| 开始激活 | POS 查询本机设备号对应任务，现场核对品牌、门店、设备号及通联配置。可重新检查，发现分配错误可确认作废。查无任务时显示设备号，联系后台分配后重试。 |
| 失败与结果未知 | 连接超时先查原结果。可修复的失败沿用原任务，比如激活码错误、过期或归属错误。实绑门店不符时系统自动处理解绑，确认解绑后才能继续，避免重复激活或占用冲突。 |
| 首次激活与重新激活 | 收钱吧终端成功后，用本次任务的预设通联参数与本机 USDK 比对。两项一致时跳过写入，继续接收主密钥。本机任一项缺失或不一致时按整组写入。任务无预设参数时主动清除本机旧值。空值或 `00` 待联调。 |
| 设置页单独开通银行卡 | 每次点设置入口都读当前设备详情的最新参数。两项一致时沿用本机参数，任一项不同时成对写入，后台缺参数时提示联系补录。沿用当前收钱吧终端，主密钥接收成功后才显示银行卡激活成功。 |
| 回到哪里 | 正常激活结束进入首页。设置中单独发起的流程在成功、暂缓或异常确认后回到设置页。流程参考图保留原画面，按钮和去向按 PRD 执行。 |

## 5. CRM 本期范围

开始讨论时拟复用运营平台两菜单的全部能力，之后确认导入批次本期留在运营平台。CRM 提供「激活任务管理」和「POS 激活管理」，承接单台分配、逐台任务查询与处理、反激活、设备信息和银行卡参数维护。

CRM 数据范围限定为当前销售或 AE 已关联的品牌。任务按目标品牌过滤，设备按当前归属品牌过滤，单台分配校验目标门店所属品牌。运营平台批量生成的任务可按品牌在 CRM 查到。权限也用于详情直达和提交操作。错绑实际门店在授权范围外时，标识字段的查看权限待评审。 [CRM 需求及验收](meta-pos-device-activation-prd.md#33-crm)
